# Отчёт по практической работе
## Автоматизация резервного копирования и очистки лог-файлов

### 1. Цель работы

Создать Bash-скрипт `backup_and_clean.sh` для автоматического резервного копирования лог-файлов, очистки их содержимого после успешного архивирования, удаления устаревших архивов и ведения журнала работы. Настроить ежедневный запуск скрипта с помощью `cron`.

### 2. Что требовалось сделать

1. Проверять, что скрипт запущен с правами `root` или через `sudo`.
2. Проверять наличие каталога `/var/log/app/` и создавать его при необходимости.
3. Архивировать все файлы с расширением `.log` в один архив формата `.tar.gz`.
4. Сохранять архивы в каталоге `/opt/backups/`, добавляя дату и время в имя файла.
5. Проверять созданный архив и только после успешной проверки очищать исходные лог-файлы, не удаляя сами файлы.
6. Удалять архивы резервных копий старше семи дней.
7. Записывать действия, ошибки и количество удалённых архивов в `/var/log/backup_script.log` с отметкой времени.
8. Настроить ежедневный запуск скрипта в 02:00 с помощью `cron`.

### 3. Выполнение работы

#### 3.1. Создание Bash-скрипта

Создан файл `backup_and_clean.sh` в домашнем каталоге пользователя. Скрипт написан на Bash и использует переменные для путей к каталогу логов, каталогу резервных копий и журналу.

Основные используемые команды и конструкции:

- `mkdir -p` — создание каталогов при необходимости;
- `date` — получение текущих даты и времени для имени архива и записей журнала;
- `tar -czf` — создание сжатого архива формата `.tar.gz`;
- `tar -tzf` — проверка возможности прочитать содержимое архива;
- `find` с параметром `-mmin +10080` — поиск архивов старше семи суток;
- `rm` — удаление устаревших архивов;
- `printf` и перенаправление `>>` — запись сообщений в журнал;
- `: > файл` — очистка содержимого файла без удаления самого файла;
- `sudo` — запуск команд с административными правами;
- `bash -n` — проверка синтаксиса скрипта.

#### 3.2. Подготовка каталогов и лог-файлов

Скрипт проверяет наличие `/var/log/app/` и создаёт его, если каталога нет. Для резервных копий используется `/opt/backups/`.

В каталоге логов были подготовлены файлы `app.log` и `error.log`. После успешного создания и проверки архива их содержимое очищается, при этом сами файлы сохраняются.

#### 3.3. Создание и проверка архива

Для каждого запуска формируется имя архива с датой и временем, например:

`/opt/backups/app_backup_2026-10-29_06-04-01.tar.gz`

В архив включаются все файлы с расширением `.log` из `/var/log/app/`. После создания выполняется проверка архива. Очистка исходных файлов производится только при успешном создании и проверке архива.

#### 3.4. Удаление старых архивов

Скрипт ищет в `/opt/backups/` архивы, соответствующие шаблону `app_backup_*.tar.gz`, возраст которых превышает семь суток. Найденные устаревшие архивы удаляются, а информация об удалении записывается в журнал. В конце работы фиксируется количество удалённых архивов.

#### 3.5. Ведение журнала

Все основные действия скрипта записываются в файл:

`/var/log/backup_script.log`

Каждая запись содержит дату и время, а также описание действия или ошибки. В журнале фиксируются начало и завершение работы, создание и проверка архива, очистка лог-файлов, удаление старых архивов и количество удалённых файлов.

#### 3.6. Настройка автоматического запуска

Для ежедневного запуска использована команда редактирования задания `cron`:

```bash
sudo crontab -e
```

В расписание добавлена строка:

```cron
0 2 * * * /usr/bin/bash /home/student/backup_and_clean.sh
```

Она задаёт запуск скрипта каждый день в 02:00 по времени виртуальной машины. Для просмотра текущего расписания использовалась команда:

```bash
sudo crontab -l
```

Состояние службы `cron` проверялось командой:

```bash
sudo systemctl status cron
```


### 3.7. Полный текст созданного скрипта

Файл `backup_and_clean.sh`:

```bash
#!/bin/bash

# Скрипт автоматического резервного копирования и очистки логов

LOG_DIR="/var/log/app"
BACKUP_DIR="/opt/backups"
SYSTEM_LOG="/var/log/backup_script.log"

# 1. Проверка прав доступа
if [[ "$EUID" -ne 0 ]]; then
    echo "ОШИБКА: запустите скрипт через sudo или от root." >&2
    exit 1
fi

# 2. Функция записи сообщений в системный лог
log_message() {
    local message="$1"
    local timestamp
    timestamp=$(date '+%Y-%m-%d %H:%M:%S')

    if ! printf '[%s] %s\\n' "$timestamp" "$message" >> "$SYSTEM_LOG"; then
        echo "ОШИБКА: не удалось записать системный лог." >&2
    fi
}

log_message "Начало работы скрипта."

# 3. Проверка и создание директории логов
if [[ ! -d "$LOG_DIR" ]]; then
    if mkdir -p "$LOG_DIR"; then
        log_message "Создана директория $LOG_DIR."
    else
        log_message "ОШИБКА: не удалось создать $LOG_DIR."
        exit 1
    fi
fi

# 4. Создание директории резервных копий
if ! mkdir -p "$BACKUP_DIR"; then
    log_message "ОШИБКА: не удалось создать $BACKUP_DIR."
    exit 1
fi

# 5. Формирование имени архива
TIMESTAMP=$(date '+%Y-%m-%d_%H-%M-%S')
ARCHIVE="$BACKUP_DIR/app_backup_${TIMESTAMP}.tar.gz"

# 6. Поиск файлов .log
shopt -s nullglob
LOG_FILES=("$LOG_DIR"/*.log)
shopt -u nullglob

if [[ ${#LOG_FILES[@]} -gt 0 ]]; then

    # Получаем только имена файлов
    LOG_NAMES=()

    for file in "${LOG_FILES[@]}"; do
        LOG_NAMES+=("${file##*/}")
    done

    # 7. Создание архива
    if tar -czf "$ARCHIVE" -C "$LOG_DIR" -- "${LOG_NAMES[@]}"; then

        # 8. Проверка архива
        if tar -tzf "$ARCHIVE" > /dev/null 2>&1; then
            log_message "Архив успешно создан и проверен: $ARCHIVE"

            # 9. Очистка исходных файлов без удаления
            CLEAN_FAILED=0

            for file in "${LOG_FILES[@]}"; do
                if : > "$file"; then
                    log_message "Очищен файл: $file"
                else
                    log_message "ОШИБКА: не удалось очистить $file."
                    CLEAN_FAILED=1
                fi
            done

            if [[ "$CLEAN_FAILED" -eq 0 ]]; then
                log_message "Очистка логов завершена успешно."
            else
                log_message "ОШИБКА: не все файлы удалось очистить."
            fi

        else
            log_message "ОШИБКА: архив поврежден. Очистка отменена."
            rm -f -- "$ARCHIVE"
        fi

    else
        log_message "ОШИБКА: создание архива завершилось неудачно."
        rm -f -- "$ARCHIVE"
    fi

else
    log_message "ВНИМАНИЕ: файлы .log не найдены. Архив не создан."
fi

# 10. Удаление архивов старше 7 суток
DELETED_COUNT=0
FAILED_COUNT=0

while IFS= read -r -d '' old_file; do
    if rm -- "$old_file"; then
        log_message "Удален старый архив: $old_file"
        ((DELETED_COUNT += 1))
    else
        log_message "ОШИБКА: не удалось удалить $old_file."
        ((FAILED_COUNT += 1))
    fi
done < <(
    find "$BACKUP_DIR" \\
        -maxdepth 1 \\
        -type f \\
        -name 'app_backup_*.tar.gz' \\
        -mmin +10080 \\
        -print0
)

log_message "Количество удаленных старых архивов: $DELETED_COUNT"

if [[ "$FAILED_COUNT" -gt 0 ]]; then
    log_message "ОШИБКА: не удалось удалить архивов: $FAILED_COUNT"
fi

log_message "Работа скрипта завершена."
exit 0
```

### 3.8. Как проверить, что всё работает

Проверки выполняются в терминале Ubuntu.

**1. Проверить синтаксис скрипта:**

```bash
sudo bash -n ~/backup_and_clean.sh
```

Если команда ничего не вывела, синтаксических ошибок не обнаружено.

**2. Запустить скрипт вручную:**

```bash
sudo bash ~/backup_and_clean.sh
```

**3. Проверить, что архив создан:**

```bash
sudo ls -lh /opt/backups/
```

**4. Посмотреть содержимое архива** (замени имя на актуальное из предыдущей команды):

```bash
sudo tar -tzf /opt/backups/app_backup_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.tar.gz
```

В списке должны отображаться файлы логов, например `app.log` и `error.log`.

**5. Проверить, что исходные файлы сохранились:**

```bash
sudo ls -l /var/log/app/
```

После успешного архивирования сами файлы должны остаться на месте. Если в них до запуска были данные, их размер после очистки обычно будет равен нулю.

**6. Проверить журнал работы:**

```bash
sudo tail -n 20 /var/log/backup_script.log
```

В журнале должны быть записи о начале и завершении работы, создании архива, очистке логов и количестве удалённых старых архивов.

**7. Проверить удаление архивов старше семи дней:**

Создать тестовый файл, имитирующий старый архив, запустить скрипт и проверить, что файл удалён:

```bash
sudo touch /opt/backups/app_backup_test_old.tar.gz
sudo touch -d '8 days ago' /opt/backups/app_backup_test_old.tar.gz
sudo bash ~/backup_and_clean.sh
sudo ls /opt/backups/
```

Файл `app_backup_test_old.tar.gz` должен исчезнуть из списка. Этот тестовый файл пустой, он используется только для проверки удаления.

**8. Проверить настройку автоматического запуска:**

```bash
sudo systemctl status cron
sudo crontab -l
```

Служба `cron` должна быть активна. В расписании должна присутствовать строка:

```cron
0 2 * * * /usr/bin/bash /home/student/backup_and_clean.sh
```

Это означает ежедневный запуск в 02:00 по времени виртуальной машины. Проверить факт запуска можно по новым отметкам времени в `/var/log/backup_script.log` после запланированного времени.


### 3.9. Подробное описание работы кода

В этом разделе разобраны основные части скрипта и объяснено, где задаются пути, время, период хранения архивов и порядок выполнения операций.

#### Переменные с путями

```bash
LOG_DIR="/var/log/app"
BACKUP_DIR="/opt/backups"
SYSTEM_LOG="/var/log/backup_script.log"
```

- `LOG_DIR` — каталог, в котором скрипт ищет исходные файлы логов с расширением `.log`.
- `BACKUP_DIR` — каталог, в который сохраняются резервные архивы.
- `SYSTEM_LOG` — файл, куда записываются сообщения о ходе работы скрипта.

Если пути нужно изменить, достаточно изменить значения этих переменных в начале файла.

#### Проверка прав администратора

```bash
if [[ "$EUID" -ne 0 ]]; then
    echo "ОШИБКА: запустите скрипт через sudo или от root." >&2
    exit 1
fi
```

`EUID` содержит эффективный идентификатор пользователя. У `root` он равен `0`. Если скрипт запущен не от имени администратора, выводится сообщение об ошибке, а `exit 1` завершает выполнение с кодом ошибки.

#### Запись сообщений в журнал

Функция `log_message` формирует отметку времени командой:

```bash
timestamp=$(date '+%Y-%m-%d %H:%M:%S')
```

Формат означает: год-месяц-день, часы:минуты:секунды. Например, `2026-10-29 06:04:01`.

Команда:

```bash
printf '[%s] %s\n' "$timestamp" "$message" >> "$SYSTEM_LOG"
```

добавляет сообщение в конец журнала. Оператор `>>` дописывает текст, не перезаписывая предыдущие записи.

#### Создание каталогов

```bash
mkdir -p "$LOG_DIR"
mkdir -p "$BACKUP_DIR"
```

Ключ `-p` создаёт каталог, если он отсутствует, и не выдаёт ошибку только из-за того, что каталог уже существует. В самом скрипте создание `/var/log/app/` выполняется только при отсутствии этого каталога; каталог резервных копий создаётся перед архивированием.

#### Формирование имени архива и время запуска

```bash
TIMESTAMP=$(date '+%Y-%m-%d_%H-%M-%S')
ARCHIVE="$BACKUP_DIR/app_backup_${TIMESTAMP}.tar.gz"
```

Дата и время включаются в имя архива. Например:

`app_backup_2026-10-29_06-04-01.tar.gz`

Это помогает отличать архивы, созданные в разные запуски. Важно: эти строки **не задают время автоматического запуска**. Они лишь формируют имя архива по текущему времени.

#### Поиск лог-файлов

```bash
shopt -s nullglob
LOG_FILES=("$LOG_DIR"/*.log)
shopt -u nullglob
```

Шаблон `*.log` выбирает файлы, имена которых заканчиваются на `.log`. `nullglob` нужен, чтобы при отсутствии подходящих файлов шаблон не остался в массиве как обычный текст. Затем настройка `nullglob` выключается.

Если файлы найдены, скрипт собирает их имена и передаёт команде `tar`.

#### Создание и проверка архива

```bash
tar -czf "$ARCHIVE" -C "$LOG_DIR" -- "${LOG_NAMES[@]}"
```

- `-c` — создать архив;
- `-z` — сжать его с помощью gzip;
- `-f` — использовать имя файла, указанное после ключа;
- `-C "$LOG_DIR"` — перейти в каталог логов перед добавлением файлов;
- `--` — обозначить конец параметров команды, чтобы имена файлов не воспринимались как ключи.

Затем выполняется проверка:

```bash
tar -tzf "$ARCHIVE" > /dev/null 2>&1
```

Ключ `-t` просит `tar` вывести список содержимого архива, `-z` указывает на gzip, `-f` задаёт файл архива. Вывод направляется в `/dev/null`, потому что важен сам результат проверки, а не печать списка в терминал. Если создание и проверка прошли успешно, скрипт переходит к очистке исходных логов. При ошибке очистка отменяется.

#### Очистка исходных логов

```bash
: > "$file"
```

Команда `:` ничего не выводит и завершается успешно. Перенаправление `>` открывает указанный файл и обнуляет его содержимое. Файл при этом не удаляется: сохраняются его имя и сам объект файла. Эта операция выполняется только после успешного создания и проверки архива.

#### Как задаются семь дней для хранения архивов

В скрипте используется команда:

```bash
find "$BACKUP_DIR" \
    -maxdepth 1 \
    -type f \
    -name 'app_backup_*.tar.gz' \
    -mmin +10080 \
    -print0
```

Параметр `-mmin` проверяет возраст файла по времени последнего изменения в минутах.

- `10080` — количество минут в семи сутках: `7 × 24 × 60 = 10080`.
- `+10080` означает, что время последнего изменения файла было более чем 10080 минут назад, то есть более семи дней назад.
- `-maxdepth 1` ограничивает поиск непосредственно каталогом `/opt/backups/`, без обхода вложенных каталогов.
- `-type f` выбирает обычные файлы.
- `-name 'app_backup_*.tar.gz'` ограничивает поиск архивами с указанным шаблоном.
- `-print0` выводит найденные пути с нулевым разделителем, чтобы корректно обрабатывать имена с пробелами и другими специальными символами.

Найденные файлы передаются циклу, в котором команда `rm` удаляет каждый старый архив. Количество успешно удалённых файлов увеличивается в переменной `DELETED_COUNT`. Ошибки удаления учитываются отдельно в `FAILED_COUNT`. В журнал записывается число удалённых архивов.

#### Как задаются два часа ночи

Время ежедневного запуска задаётся **не внутри Bash-кода**, а в расписании `cron`. Используется строка:

```cron
0 2 * * * /usr/bin/bash /home/student/backup_and_clean.sh
```

Первые пять полей имеют следующий смысл:

| Поле | Значение | Значение для расписания |
|---|---:|---|
| Минуты | `0` | В начале часа, на нулевой минуте |
| Часы | `2` | В 02:00 |
| День месяца | `*` | Каждый день месяца |
| Месяц | `*` | Каждый месяц |
| День недели | `*` | Любой день недели |

Таким образом, запись означает запуск скрипта ежедневно в 02:00 по часовому поясу виртуальной машины. В этой строке `/usr/bin/bash` запускает скрипт интерпретатором Bash, а `/home/student/backup_and_clean.sh` — путь к самому файлу. Служба `cron` должна быть запущена.

#### Что происходит при каждом запуске

1. Скрипт проверяет права администратора.
2. Записывает в журнал сообщение о начале работы.
3. Проверяет каталог логов и создаёт необходимые каталоги.
4. Находит файлы `.log`.
5. Создаёт архив с датой и временем в имени.
6. Проверяет архив.
7. При успешной проверке очищает содержимое исходных лог-файлов, не удаляя их.
8. Находит и удаляет архивы старше семи суток.
9. Записывает количество удалённых архивов и сообщение о завершении работы.

## Дополнительная проверка: добавление тестовых данных в логи

Чтобы проверить резервное копирование на тестовых сообщениях, вручную добавьте строки в `error.log` и `app.log`.

### 1. Добавление тестовых сообщений

```bash
sudo mkdir -p /var/log/app
echo "ERROR: Test error message 1" | sudo tee -a /var/log/app/error.log
echo "ERROR: Test error message 2" | sudo tee -a /var/log/app/error.log
echo "INFO: Test application message" | sudo tee -a /var/log/app/app.log
```

### 2. Проверка исходных логов перед запуском

```bash
sudo cat /var/log/app/error.log
sudo cat /var/log/app/app.log
```

В файлах должны отображаться добавленные тестовые сообщения.

### 3. Запуск скрипта вручную

```bash
sudo /usr/bin/bash /home/student/backup_and_clean.sh
```

После успешного создания и проверки архива скрипт очищает исходные `.log`-файлы, но не удаляет их.

### 4. Поиск последнего архива

```bash
sudo ls -lt /opt/backups/
```

Скопируйте имя самого нового архива из списка.

### 5. Проверка данных внутри архива

Подставьте фактическое имя архива вместо `ИМЯ_АРХИВА`:

```bash
sudo tar -xOzf /opt/backups/ИМЯ_АРХИВА error.log
```

Для проверки `app.log`:

```bash
sudo tar -xOzf /opt/backups/ИМЯ_АРХИВА app.log
```

Опция `-O` выводит содержимое файла на экран без распаковки его в каталог.

### 6. Проверка журнала скрипта и исходных файлов

```bash
sudo tail -n 20 /var/log/backup_script.log
sudo ls -lh /var/log/app/
```

В журнале ищите сообщения об успешном создании и проверке архива и об очистке исходных файлов. После успешного запуска исходные файлы должны существовать, но иметь размер 0 байт.

**Ожидаемый результат:** тестовые сообщения присутствуют внутри созданного архива, а исходные `.log`-файлы остаются на месте и очищаются после успешной проверки архива.
